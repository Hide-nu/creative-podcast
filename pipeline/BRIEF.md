# アイデアの分岐点 台本執筆ブリーフ（全ライター共通）

番組：毎朝1本、「外部評価の旗」に刻まれた人・プロダクト・キャンペーンが、**どんな試行錯誤を経て世に出たのか**を追う日本語の音声番組。聴き手はクリエイティブ・プロダクトづくりをしている個人で、いちばん知りたいのは「革新的なアイデアが、どういう経緯で生まれ、形を変え、リリースに至ったか」というアイディエーションのプロセス。完成品の説明や理論の講義ではなく、作り手の迷いと判断の連続を聴かせる番組である。音声合成（VOICEVOX）で読み上げる。

## 分量と構成（約16分・本文6,500〜7,000字。必ずこの範囲に収める）
全体の6割以上を 3〜5 の「生まれるまで」に使う。完成品の紹介と理論は短く。
1. オープニング：「おはようございます。アイデアの分岐点です。今日の題材は、〇〇です。」で始め、完成品を一言で示し、「今日は、これが生まれるまでの道のりを追います」と予告する（約0.5分）
2. 完成したものと、変えた行動：何ができて、誰のどんな行動が変わったかを短く（約1分）
3. 出発点：誰が、いつ、どんな課題・違和感・依頼・制約から考え始めたか。当時の常識や手元の資源（予算、人数、技術、締め切り）も具体的に（約2分）
4. 試行錯誤の経緯：時系列で追う中心パート（約6分）
   - 最初の案はどんな形だったか。最終形とどこが違ったか
   - 検討して捨てた案と、捨てた理由
   - 試作・テスト・社内プレゼン・クライアントや上司の反対・技術的な壁・失敗と、そのとき何を変えたか
   - アイデアが今の形に「化けた」転機の瞬間。誰の一言、どんな発見、どんな偶然だったか
   - **分岐点を最低3つ**、「AとBの選択肢があり、こういう理由でこちらを選んだ」という形で具体的に描く。年月、人名、本人の発言（出典で確認できたもの）、数字を入れる
5. リリースの判断：何を削り、何を残して出したか。出した直後の反応と、そこからの修正（約1.5分）
6. 理論で読み直す：4 の分岐点の判断を、1〜2個の理論（心理学・行動経済学・デザイン・経営など）で読み直す。提唱者の名前を添え、必ず具体的な判断に結びつける。理論の一般的な解説は短くする（約2分）
7. 影の側面：批判・社会との摩擦・うまくいかなかった点。必ず扱う（約1分）
8. 今日の自分への持ち帰り：この経緯から真似できる「考え方の手順」を3つと問い（約1分）。最後は「今日、誰のどんな行動を変えようとしますか。」につながる問いを置き、最終行は必ず「迷い切れ、くよくよし切れ、お前なら前にすすめる。」で締める

歴史的背景や先行者は、3 と 4 の中で「なぜその時その判断ができたか」を説明するのに必要な分だけ入れる。独立した章にしない。

## 経緯の調べ方
- 完成品の紹介記事や受賞記事だけで書かない。経緯は次のような一次情報に近いものから探す：作り手本人のインタビュー・講演・ポッドキャスト出演・著書・ブログやポストモーテム、広告賞のケースフィルムや審査会での発表、社内の初期資料や初期バージョンの記録、開発者向けカンファレンスの講演、関係者の証言を集めた書籍や長編記事。
- 英語・日本語の両方で「origin」「how we made」「behind the scenes」「early prototype」「pitch」「rejected ideas」「post-mortem」や「誕生秘話」「開発秘話」「ボツ案」などを組み合わせて探す。
- **推測で経緯を埋めない。** 確認できない部分は「その経緯は、公開された記録にはほとんど残っていません」と正直に言い、確認できた事実だけで語る。「〜と見られます」「〜でしょう」で作り手の意図を想像して書くのは禁止。
- 確認できる分岐点が3つに満たない題材は、無理に書かず、meta の note に「経緯の情報が薄い」と書いて、差し替え候補を1つ挙げる。

## 事実確認
- 書く前に必ずWebSearch/WebFetchで事実（年、人物、数字、受賞歴）を確認する。ネタ帳のメモの前提が誤っていたら、正しい事実で書き、meta の note に誤りを書く。
- 作り手の発言は出典で確認できたものだけを要約で伝える。不確かなものは「と言われている」と明示する。数字は確認できたものだけ。
- 研究の信頼性に問題があるもの（再現性の危機など）はそう言う。

## 音声向けの書き方（厳守）
- 1行に1文。一文は40字前後までに区切る。段落の区切りに空行は入れなくてよい（入れてもよい）。
- 見出し記号、箇条書き、番号、括弧書きの補足、URL、絵文字は使わない。話し言葉で書く。
- 英字・ローマ字の固有名詞はすべてカタカナで書く（例：Nike → ナイキ、Spotify → スポティファイ、iPhone → アイフォーン、TIME → タイム誌）。英字を一文字も残さない。
- 数字は読みやすく：年は「二〇〇八年」または「2008年」どちらでもよいが、大きな数は「約三億人」「十億ドル」のように漢数字＋万・億で。小数・パーセントは「三十パーセント」のように。
- 読み間違えやすい語はひらがなにする（例：一日→いちにち/ついたち を文脈でひらがな、行った→おこなった/いった、生物→せいぶつ）。人名で難読なものはひらがな・カタカナで。
- 「〜」「／」「・」の多用は避ける。記号「？」「！」は使ってよい。

## 出力（ファイルに書く。チャットに本文を貼らない）
1. 台本本文：`/root/pod/scripts/<ファイル名>.txt`（UTF-8、上記ルールの本文のみ。出典は含めない）
2. メタ情報：`/root/pod/meta/<ファイル名>.json`
   ```json
   {"page_id": "<与えられたページID>", "title": "<ネタ帳の名前>", "chars": <本文文字数>,
    "award": "<受賞年の欄に入れる短い文。例：2013（カンヌライオンズ グランプリ5部門）。なければ主要な評価を1行>",
    "note": "<ネタ帳の前提の誤りや差し替えがあれば。なければ空文字>",
    "turning_points": ["<台本で描いた分岐点を1つ1行で。『年月：選んだこと／捨てたこと／理由（出典名）』>", "..."],
    "sources": "<出典を1段落で。『媒体名「記事名」』を読点でつなぐ。URLは書かない>"}
   ```
3. 最後に、本文の文字数（改行を除く）が6,500〜7,000字であること、英字（A-Za-z）が0文字であることを python で確認し、満たさなければ直す。
4. 両方を書き終えたら、空ファイル `/root/pod/scripts/<ファイル名>.done` を作る（これが音声合成開始の合図。台本を確定してから作ること）。

5本を1本ずつ順番に仕上げ、1本終わるごとに .done を作って次へ進むこと（合成が並行して進むため）。
